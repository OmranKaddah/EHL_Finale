The earlier submissions were marked as not eligible (Quality 0, with 0 model calls) because the agent crashed immediately during the sandbox initialization phase before it could even start evaluating the RFQ. 

When we ran a `test-run` to trace the error, we captured the following exception during the setup phase:

```python
Traceback (most recent call last):
  # ...
  File "/work/.venv/lib/python3.12/site-packages/hackathon_toolkit/rfq/runtime.py", line 365, in run_agent
    seconds=run_seconds(run, args.max_seconds),
  File "/work/.venv/lib/python3.12/site-packages/hackathon_toolkit/rfq/runtime.py", line 310, in run_seconds
    expires = datetime.fromisoformat(run["expires_at"].replace("Z", "+00:00"))
AttributeError: 'int' object has no attribute 'replace'
```

**The Cause:**
The `expires_at` value provided by the evaluation sandbox was an integer (a UNIX timestamp in milliseconds, which also caused a `ValueError: year 58744 is out of range` when parsed directly as seconds), whereas the local mock/scout data provided it as an ISO string (which has a `.replace()` method). 

**The Fix:**
I updated `run_seconds` in `runtime.py` to correctly handle both ISO strings and millisecond UNIX timestamps:
```python
        val = run["expires_at"]
        if isinstance(val, (int, float)):
            if val > 1e11: # Handle millisecond timestamps
                val = val / 1000.0
            expires = datetime.fromtimestamp(val, tz=timezone.utc)
```

We verified this fix works perfectly: our active test-run (`run_677b9ebcc1148073`) is currently progressing through the evaluation and has made **79+ model calls** without crashing. Our latest submission (`sub_5880105816509f4a`) includes this fix and is currently actively running in the evaluation queue!
